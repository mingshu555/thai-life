# 饮食与点餐水果排序与泰国菜单双面翻卡设计

**日期：** 2026-08-20  
**状态：** 用户已确认设计；待用户审阅本文档后进入实施

## 背景

「饮食与点餐」课程已包含一组泰国常见水果词，但这些词目前位于课程内容靠后的位置。学习流应先覆盖基础食物，再连续学习水果，之后进入饮品。

「泰国常见菜单」浏览页已具备正面、背面及 `rotation3DEffect`，但两面在 3D 旋转期间没有可靠地进行背面隐藏，可能同时显示、重叠或镜像，未呈现明确的正反面翻卡效果。

## 目标

1. 将 `food_dining` 中的全部水果词移至基础食物词之后、饮品词之前，并维持水果组内部的既有顺序。
2. 将菜单卡实现为清晰的正反双面翻卡：任何时刻仅显示朝向用户的一面，翻转时不叠字、不镜像透出。
3. 保留现有交互：点按翻转，横向滑动切换菜单卡，切换卡片后回到正面。

## 非目标

- 不增加或删除任何课程词条、例句、音频、图片或菜单卡片。
- 不改变水果组内顺序、词条 ID、`audioID`、例句、例句音频或学习记录。
- 不改变菜单卡正反面的文案、资源结构、拆解内容或页面入口。
- 不实现书页卷曲、卡组堆叠或新的菜单筛选功能。

## 一、课程内容排序

### 排序规则

在 `ThaiLife/Resources/Content/items.json` 的 `food_dining` 单元中：

1. 保留基础食物及现有餐厅点餐内容的既有相对顺序；
2. 将带有 `fruit` 标签的水果词条作为一个连续区段，插入基础食物词之后；
3. 将该水果区段置于第一条饮品词之前；
4. 水果区段内部完全沿用现有顺序；
5. 所有后续饮品、甜品和菜品词的相对顺序保持不变。

### 数据完整性

这是一项数组顺序调整，不改动词条的字段值。因而 `id`、分类、标签、先修关系、例句文本、中文整句翻译和 `audioID` 均保持不变，现有音频资源无需重新生成。

## 二、菜单双面翻卡

### 视图结构

菜单卡仍由正面和背面组成：

- **正面：** 菜品图、分类、完整泰语菜名、中文菜名；
- **背面：** 完整泰语菜名、中文菜名及词语拆解。

实现将使用独立的正反面视图和共享的 3D Y 轴旋转进度，而不是让两个面在同一层始终可见。翻转进度跨越 90° 时，面向用户的那一面成为唯一可见面；背向用户的一面会被隐藏，防止文字重叠或镜像。

### 交互与动画

- 点按卡片空白区域或内容区域切换 `isFlipped`；
- 使用弹簧曲线完成 0° ↔ 180° 的 Y 轴旋转；
- 横向手势优先用于上一张/下一张卡；垂直拖动和未达到阈值的拖动不会切换卡片；
- 切换菜单卡时，将翻卡状态重置为正面；
- 卡片保持现有圆角、阴影、尺寸约束和背面可滚动的词语拆解。

### 实现选择

采用“**双面卡片 + 3D 背面隐藏**”方案：这是相较于透明度交叉淡入淡出更接近真实翻卡的实现，同时比自定义书页卷曲动画简单、稳定，并且不会增加与背面滚动视图的手势冲突。

## 三、测试与验收

### 自动化验证

1. 内容校验通过：
   ```bash
   python3 tools/validate_content.py
   ```
2. 菜单资源、菜单数据加载和词语拆解重建测试继续通过；
3. 增加/更新测试，以验证：
   - `food_dining` 的水果词为连续区段；
   - 水果区段在饮品区段之前；
   - 菜单翻卡使用独立正反面及明确的背面隐藏逻辑；
   - 切换菜单卡会回到正面。
4. iOS 单元测试构建通过：
   ```bash
   xcodebuild -project ThaiLife.xcodeproj \
     -scheme ThaiLife \
     -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max' \
     test
   ```

### 手动验收

- 在「饮食与点餐」浏览时，基础食物之后直接进入连续的水果词，随后才进入饮品；
- 在「泰国常见菜单」中点按卡片，正面平滑翻至背面，过程中不出现两面内容叠加或背面文字镜像；
- 再次点按可翻回正面；
- 左右滑动可切菜，切换后的卡片始终从正面开始；
- 背面拆解区域仍可以垂直滚动。
