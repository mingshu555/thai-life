# 收藏练习日期分组列表与卡片浏览设计

**日期：** 2026-08-16
**状态：** 已完成设计，待用户审阅后进入实施

## 背景

首页「收藏练习」当前直接推入 `ReviewSessionView(route: .favorites)`，跳过了内容选择列表，且无法让用户按收藏时间浏览自己的收藏。

课程功能已有明确的两层浏览体验：先进入内容列表，再从用户点选的内容进入可前后切换的卡片浏览。本功能将收藏入口对齐这一体验，同时利用现有 `FavoriteRecord.favoritedAt` 展示收藏日期。

## 目标

1. 点击首页「收藏练习」时，先展示收藏内容列表，不直接进入复习卡片。
2. 列表按用户本地日历日的收藏日期分组，最新日期和最新收藏均排在前面。
3. 用户向上滚动时，当前日期分区标题固定在列表顶部，并在跨日期时自然切换。
4. 点击一条收藏内容后，进入从该条开始的收藏卡片浏览；可在当前全部收藏中前后切换。
5. 保持课程浏览与收藏浏览均为非 FSRS 浏览模式，不写入评分、复习日志、排程或草稿。

## 非目标

- 不改变课程列表、课程浏览或其「练习」工具栏行为。
- 不改变普通日常复习、薄弱项复习、易混词复习或它们的 FSRS 队列。
- 不增加日期筛选、搜索、批量取消收藏、编辑模式或手动排序。
- 不改变收藏数据模型；`FavoriteRecord.contentID` 和 `favoritedAt` 已满足本功能。
- 不新增音频资源，也不改变主词、例句或分段音频的播放流程。

## 信息与排序规则

### 数据加载

新增 `StudyStore` 查询接口，获取所有 `FavoriteRecord`，按 `favoritedAt` 降序、`contentID` 升序进行稳定排序。列表层将每条记录与当前打包内容中的 `ContentItem` 匹配。

若某条收藏记录在当前内容包中不存在对应 `ContentItem`，该记录不会渲染到列表，也不会被加入浏览队列；应用不崩溃，并保留该持久化记录以避免本功能擅自删除用户数据。

### 日期分组

- 使用设备当前 `Calendar` 和时区，把 `favoritedAt` 归入其本地自然日。
- 日期组按日期降序排列。
- 组内按完整 `favoritedAt` 降序；时间完全相同则按 `contentID` 升序，保证每次加载顺序一致。
- 不合并「本周」或「本月」等相对区间：每个自然日独立成组。

### 日期标题文案

- 当天：`今天 · M月d日`
- 昨天：`昨天 · M月d日`
- 其他日期：`yyyy年M月d日`

标题的「今天」和「昨天」在每次列表显示时根据设备的当前本地日期计算；历史收藏的实际分组日期不变。

## 界面与交互

### 首页入口

`TodayView` 的「收藏练习」导航目标从直接的 `.favorites` 复习会话替换为新的收藏列表页。快速入口保持原有图标、标题和副标题。

### 收藏列表页

新增 `FavoriteListView` 与其轻量 view model／展示模型：

- 导航标题为「收藏练习」。
- 使用 `ScrollView`、`LazyVStack` 和 `pinnedViews: [.sectionHeaders]` 渲染日期分区。
- 分区头部使用应用现有的次级文字和背景色，能在用户上滑时固定于顶部；下一日期分区抵达时系统布局自然顶替前一标题。
- 每行复用或抽取课程内容列表的视觉规范：泰文作为主标题，中文释义作为次级文本，全行具有清晰且单一的点击区域。
- 点击一行后导航到该条的收藏卡片浏览。
- 没有可展示收藏时显示空状态「暂无收藏内容」；加载错误时显示现有应用风格的简洁错误文案，且不进入卡片页。

### 收藏卡片浏览

`ReviewSessionRoute` 新增独立 `favoriteBrowse(startContentID:)` 路由，而不是复用会写入 FSRS 状态的 `.favorites` 路由。

该路由的行为：

1. 以与收藏列表完全相同的稳定排序载入所有有效收藏内容。
2. 将浏览 cursor 定位到 `startContentID`，使用户点选的条目先显示。
3. 复用现有 `ReviewSessionView`、`ReviewSessionViewModel`、翻卡、前后滑动和音频能力。
4. 显示浏览计数与前后导航；首尾不可继续时维持已有回弹／禁用行为。
5. 不显示评分按钮，不调用评分，不生成 review log，不改 FSRS 状态，不保存或恢复学习草稿。
6. 返回时仅回到收藏列表，保留列表的导航栈位置。

原 `.favorites` 路由保留其现有实现与语义，供未来若有独立「对收藏进行 FSRS 练习」入口时使用；首页本次改为进入列表而非该路由。

## 架构边界

- `FavoriteListView` 负责展示、日期分组和列表到浏览路由的导航。
- `StudyStore` 负责从 SwiftData 读取收藏记录及稳定的数据库排序；不负责内容包匹配或文案格式化。
- 列表 view model／纯展示辅助负责把收藏记录同 bundle 内容匹配、过滤孤立记录、按本地日期分组并生成标题。
- `ReviewSessionViewModel` 负责 `favoriteBrowse` 的队列加载与起始 cursor 定位；它不负责列表日期分组。
- 不修改 `ContentItem`、`FavoriteRecord` 的持久化 schema。

## 测试与验收

### 单元测试

1. 收藏展示模型按本地自然日正确分组，日期组按最新优先排列。
2. 同日收藏按完整时间倒序；相同时间使用 `contentID` 保持稳定顺序。
3. 「今天」「昨天」和历史日期标题依据指定 `Calendar`／当前日期生成，避免测试依赖机器当天时间。
4. 内容包缺失的收藏记录会被安全过滤，不出现在列表或浏览队列。
5. 点击收藏行生成 `favoriteBrowse(startContentID:)`，且该条在浏览队列中成为初始 cursor。
6. `favoriteBrowse` 包含全部有效收藏并保持列表排序，不受每日新卡上限限制。
7. `favoriteBrowse` 不生成复习日志、不保存草稿、不改变 FSRS 状态；既有 `.favorites` 的行为保持通过。

### UI／路由测试

1. 首页「收藏练习」的 destination 是收藏列表页，而非直接的 `.favorites` 会话。
2. 收藏列表行点击后进入对应收藏卡片浏览。
3. 列表结构包含日期 section header；实现使用 `pinnedViews: [.sectionHeaders]`，确保真机滚动时标题悬浮。

## 成功标准

- 首页收藏入口始终先进入日期分组收藏列表。
- 每条可用收藏恰好显示在其收藏日期对应的分区中，且排序稳定。
- 上滑时当前日期标题悬浮，跨日期时准确切换。
- 点击任意收藏可从该条进入完整收藏浏览队列。
- 本功能不对 FSRS、日志、草稿、课程浏览、内容包或音频播放造成副作用。
